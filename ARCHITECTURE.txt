Chap Project Structure
======================

## 앱 소개

Chap — 키보드 단축키 한 번으로 웹사이트·앱·폴더를 원하는 화면, 원하는 크기로 즉시 여는 macOS 메뉴바 런처.

## 데이터 모델

Site 모델 필드:
  - name: String              사이트 이름
  - url: String               URL (launchType=url일 때 사용)
  - width: Int                윈도우 너비
  - height: Int               윈도우 높이
  - displayName: String?      대상 디스플레이 이름. UI 표시 + 폴백 매칭용
  - displayIdentifier: String? 대상 디스플레이 UUID(CGDisplay). 매칭 우선순위 1순위.
                              동일 모델 외장 모니터가 여러 대여도 물리 디스플레이별로 달라 정확히 구분됨.
                              nil이면(구버전 config/Follow Cursor) displayName으로 폴백.
                              displayName/displayIdentifier가 둘 다 nil이면 Follow Cursor(커서 화면)
  - windowSizePreset: String? 프리셋 ID (Follow Cursor면 내장 화면 기준, 지정 화면이면 대상 화면 기준, nil이면 Custom)
  - displaySizeOverrides: [DisplaySizeOverride] 화면별 size/preset override. 실제 실행 화면과
                              UUID → unique displayName 순으로 매칭되면 기본 size보다 우선 적용
  - launchType: LaunchType    url | app | finder | shell
  - appPath: String?          앱 경로 (launchType=app)
  - script: String?           스크립트 내용 (launchType=shell)
  - folderPath: String?       폴더 경로 (launchType=finder)
  - shortcut: String?         커스텀 단축키 ("T" → ⌥T)

※ 윈도우 위치(x, y)는 저장하지 않음 — 항상 대상 화면 중앙에 자동 배치.


## 핵심 기능

- 글로벌 단축키 (⌥., ⌥커스텀키, ⌥,) — RegisterEventHotKey로 정확한 조합만 시스템 등록
  (일반 키 입력은 Chap을 거치지 않으며 접근성 권한과 독립)
- URL → HTTP(S) URL 검증 후 Chrome --app 모드 + 단일 request coordinator 직렬 실행 + AX readback 검증
- App → 실행 전 baseline 대비 첫 새 창 하나, 없으면 focused window 하나 + AX readback 검증
  (Office는 리사이즈 가능한 비표준 문서창과 시작창→문서창 전환을 추가 관찰)
- AX bounds 결과: position/size set error와 실제 readback을 반환하고 fully/partial/failed로 기록
  - partial/failed는 판정 근거(요청 대비 실제 position/size, 어느 축이 tolerance를 벗어났는지,
    AX 에러 코드)를 통합 로그와 CSV의 detail 열에 함께 남김
  - 리사이즈 대상 창을 못 찾고 끝나면 창 개수·focused 창 메타데이터를 detail 열에 기록
    (통합 로그 보존 기간이 짧아 며칠 뒤 원인 추적이 불가능해지는 것을 방지)
- URL/App AX 리사이즈 실패 시 권한 상태를 재확인하고, 권한이 빠진 경우 상태바 경고 + 1회 알림
- Settings 저장: 선택 항목이 아닌 전체 sites 배열의 필수값·HTTP(S) URL·크기·preset·중복 검증
- Import: 안전 정규화 후 전체 validation, 차단 이슈 시 파일/VM 무변경, fixes/warnings 표시
  - 성공 시 일반 저장 경로를 사용해 Login Item 상태와 메뉴를 즉시 반영
- Legacy displayName: unique name만 UUID 보강; connected UUID는 displayName 보강/갱신;
  stale UUID 갱신, ambiguous/disconnected는 재선택 안내
- Settings/QA/Welcome 중 마지막 관리 창 종료 시 activation policy를 accessory로 복원
- 숫자 width/height는 draft로 편집해 Enter/blur 때 commit하며 실제 변경 때만 Custom 전환
- Follow Cursor 미니맵은 각 연결 화면에 저장된 화면별 size/default size preview를 동시에 표시하고,
  클릭한 화면을 size/preset 편집 대상으로 사용. 각 preview 박스 왼쪽 위에 preset 이름 표시
- Finder → 폴더 열기 + 리사이즈 (단일 AppleScript, 딜레이 없음)
- Shell → 스크립트 실행 (리사이즈 없음)
- 멀티 모니터 지원 + Display Picker로 고정 디스플레이 선택, Follow Cursor로 커서 화면 실행
- 윈도우 항상 대상 화면 중앙 배치 (centeredBounds 함수)
- 크기 프리셋: Compact, Focus, Standard, Comfortable, Wide, Tall, Workspace, Max, Custom
- Follow Cursor 디스플레이 프리셋은 내장 화면 기준 크기로 계산 후 커서 화면에 맞춤
- 화면별 size override: 외장 디스플레이가 빠져 fallback 화면에서 실행될 때 해당 화면 전용
  preset/custom size가 있으면 우선 적용. Follow Cursor 상태에서 Display Preview로 화면을 고른 뒤
  Size Preset/Width/Height를 바꾸면 override가 자동 생성되고, Use Site Default로 해당 화면 override를 제거
- 클릭 편집 + 자동 저장 (Enter/포커스 이동 시)
- 사이트별 커스텀 단축키 (optional, 정확히 한 글자, 중복 체크, 예약키 ./, 차단)
  - 단축키 정규화(sanitizedShortcuts): UI 저장뿐 아니라 config 로드(loadConfig)·Import
    경로에서도 다글자·중복(대소문자 무시, 앞의 것 유지)·예약키(./,)·공백을 정리하고,
    config 로드 중 바뀐 값은 즉시 저장. 손으로 편집한 ~/.chap.json이나 Import JSON의
    잘못된 단축키가 런타임이나 다음 실행에 새어 들지 않음
- 사이트 중복 체크 (동일 URL/앱/폴더 저장 차단)
- 필수 필드 미입력 시 저장 차단 (URL/앱경로/폴더/스크립트)
- 사이트 검색 (사이드바 이름 필터)
- 사이트 추가 시 Name 필드 자동 포커스 + 타입별 초기 추천 크기(URL Standard 상당, App Comfortable 상당, Finder Compact 상당)
- Import (파일/Paste JSON/드래그앤드랍) + Export → ~/Downloads
- ConfigStore가 config 읽기/쓰기/백업(.bak)/레거시 정리를 일원화; 파싱 실패 시 기본값 복구
- 레거시 필드 자동 정리 (x, y, hotkey, showGhostWindow, runInBackground)
- 타입별 그룹 사이드바 + 메뉴바 구분선
  - 검색 중이 아니면 url/app/finder/shell 네 섹션을 항상 표시하고, 빈 섹션은
    "Add <Type>" 행으로 해당 타입 항목을 바로 추가 (검색 중에는 매칭 없는 섹션 숨김)
- 드래그앤드랍 순서 변경 (같은 타입 내에서만)
- 방향키(↑↓) 목록 이동
- Q&A 페이지 (메뉴바에서 접근)
- 설정 창은 770x600 크기로 커서 화면 중앙에 표시
- Guide Window (리사이즈 위치 미리보기)
  - 토큰 기반 소유권: show가 토큰을 반환하고 dismiss(token)은 그 토큰이 현재일 때만 자기 창을 닫음.
    빠른 연속 실행 시 stale한 dismiss 완료 핸들러가 새 창을 죽여 유령 창이 남던 레이스를 방지
- 접근성 권한 안내 직후 자동 재시도 + 권한 제거 감지
- Launch at Login (SMAppService)
- Restart (메뉴바) / Restart App·Uninstall (설정 창 하단 folder 메뉴)

## 런처 타입별 동작

  URL:     HTTP(S) URL 검증 → Chrome --app 모드 실행 → AX API로 새 윈도우 감지 → position/size 설정
  App:     NSWorkspace.openApplication → AXObserver(kAXWindowCreated) → 리사이즈 가능 윈도우 중앙정렬
  Finder:  단일 AppleScript로 열기+리사이즈 동시 (딜레이 없음)
  Shell:   Process로 스크립트 실행 (리사이즈 없음)

리사이즈 전략:
  URL (Chrome 실행 중):  AX API 폴링 50ms 간격 (캐싱한 Chrome PID에서 새 윈도우 비교 감지, 최대 6초)
  URL (콜드 스타트):     AX API 폴링 100ms 간격 (최대 10초)
  App (실행 중):         AXObserver + 50ms 재스캔, 새 창이 없으면 0.2초 후 focused 창 하나 처리
  App (콜드 스타트):     AXObserver + 50ms 재스캔 (일반 최대 20초, Office 최대 30초),
                        focused fallback은 timeout 이후
  App (AXObserver 실패): 폴링 폴백 120ms 간격
  Finder:               딜레이 없음 (열기+리사이즈 단일 스크립트)

Chrome 윈도우 감지 방식:
  1. 모든 요청을 단일 requestCoordinator serial queue에서 처리
     (cached Chrome PID baseline → open -na Process → 새 창 polling → AX readback 검증).
     이전 요청 완료 전 다음 Process를 시작하지 않아 빠른 연속 launch도 요청과 생성 창이
     1:1로 대응함. queue wait와 processing latency를 분리해 로그에 기록
  2. 실행 전 캐싱한 Chrome PID의 전체 윈도우 목록(AXUIElement[]) 저장
     - running 상태에서 AX 읽기가 순간적으로 빈 목록을 반환할 수 있어 최대 5회(30ms 간격)
       재시도해 스냅샷을 확보 (captureExistingWindows). 빈 스냅샷을 기준으로 삼으면 기존 창이
       새 창으로 오인돼 리사이즈되는(사용자 창이 튀는) 문제를 방지. 진짜 무창 Chrome은 빈 배열 유지
  3. 실행 후 동일 PID를 폴링하고 CFEqual로 이전 목록과 비교하여 첫 새 윈도우 식별
  4. ClaimedWindowRegistry가 이미 처리한 창의 재사용을 방어적으로 차단하고 닫힌 창은 pruning
  5. position/size 설정 후 실제 값을 읽어 tolerance 내 일치 여부를 fully/partial/failed로 기록
  6. 새 윈도우를 못 찾으면 타임아웃 (실패 로그)

App 윈도우 감지 방식 (AXObserver):
  1. openApplication 전 기존 AX window baseline을 캡처
  2. AXObserverCreate로 kAXWindowCreatedNotification 구독 + 50ms 재스캔
     (CFRunLoopRunInMode 0.05초 단위로 콜백 처리와 재스캔을 겸함)
  3. baseline에 없는 첫 표준 새 창 하나만 리사이즈 (기존 여러 창 일괄 변경 금지)
  4. Office 앱은 focused fallback/시작창 리사이즈 후에도 리사이즈 가능한 비표준 문서창과
     시작창→문서창 전환을 grace 동안 추가 관찰하고, 처리 완료한 창은 다시 적용하지 않음
  5. 실행 중 앱은 새 창이 0.2초 안에 없으면 focused 표준 창 하나를 즉시 처리;
     cold 앱은 timeout까지 새 창을 기다린 뒤 focused fallback
  6. AXWindow 역할과 position/size settable을 검증해 AXHelpTag 등 보조 요소를 제외
  7. AXObserver 생성 실패 시에도 Office 문서창 교체와 grace를 포함한 동일한 polling 정책 사용
  8. 각 적용 후 실제 position/size readback으로 fully/partial/failed 판정

리사이즈 CSV (DEBUG 전용):
  - ResizeLogger가 NSLock으로 디렉터리 생성, 헤더 확인/생성, append를 직렬화
  - size는 화면 fitting과 화면별 override를 반영해 AX에 실제 요청한 WxH
  - App total_time은 첫 fully/partial 적용 시점이며 failed 시도는 latency로 기록하지 않음


## 사용 API / 프레임워크

### ApplicationServices (Accessibility API)
  문서: https://developer.apple.com/documentation/accessibility/accessibility-api
  용도: 앱 윈도우 리사이즈 (AppLauncher/ChromeLauncher), 권한 확인
  - AXUIElementCreateApplication(pid)         앱의 AX 요소 참조 생성
  - AXUIElementCopyAttributeValue             윈도우 획득 (kAXFocusedWindow / kAXWindows)
  - AXUIElementSetAttributeValue              윈도우 position/size 설정
  - AXValueCreate(.cgPoint / .cgSize)         좌표/크기 값 생성
  - AXObserverCreate / AXObserverAddNotification  윈도우 생성 이벤트 구독
  - AXIsProcessTrusted()                      접근성 권한 확인 (AccessibilityPermission)
  - AXIsProcessTrustedWithOptions()           접근성 권한 요청 다이얼로그 (AccessibilityPermission)
  - CFEqual()                                 윈도우 동일성 비교

### AppKit (NSWorkspace)
  용도: 앱 실행, 실행 중 앱 감지
  - NSWorkspace.shared.openApplication(at:configuration:)   앱 실행 (pid 콜백)
  - NSWorkspace.shared.runningApplications                  실행 중 앱 목록 조회

### Carbon (HIToolbox)
  용도: 글로벌 키보드 단축키
  - RegisterEventHotKey / UnregisterEventHotKey  정확한 Option 조합 등록·해제
  - InstallEventHandler                         등록된 단축키 이벤트 수신
  - TISCopyCurrentASCIICapableKeyboardLayoutInputSource / UCKeyTranslate
                                                 현재 키보드 배열의 문자→keyCode 매핑
  - kTISNotifySelectedKeyboardInputSourceChanged ASCII 키보드 배열 ID 변경 시 전체 재등록

### AppleScript (osascript via Process)
  용도: Finder 윈도우 제어 전용
  - Finder: "tell application Finder" → open + bounds 설정
  ※ AppLauncher, ChromeLauncher는 AX API 직접 사용 (성능 최적화)

### NSScreen
  용도: 멀티 모니터 좌표 계산, 대상 화면 결정
  - NSScreen.screens                  전체 디스플레이 목록
  - CGDisplayCreateUUIDFromDisplayID  디스플레이 안정 고유 ID (displayUUID) — 매칭 1순위,
                                      동일 모델 외장 모니터 다중 사용 시에도 정확히 구분
  - NSScreen.localizedName            디스플레이 이름 매칭 (UUID 실패 시 폴백)
  - visibleFrame / frame              좌표 변환 (NSScreen ↔ AppleScript 좌표계)

  디스플레이 매칭(resolvedDisplayIndex, 순수 함수): displayIdentifier(UUID) → unique displayName →
  커서 화면 순. 같은 이름이 여러 개면 임의 화면을 고르지 않고 재선택 상태로 유지한다.

### ServiceManagement
  용도: Login Item 등록/해제
  - SMAppService.mainApp.register()   로그인 시 자동 실행 등록
  - SMAppService.mainApp.unregister() 자동 실행 해제

## 리사이즈 성능 개선 이력 (2026-06-22)

### 변경 전 (AppleScript 방식)
  구조: 앱 실행 → 고정 딜레이 → Process fork(/usr/bin/osascript) → AppleScript → System Events/Chrome

  | 타입 | 상태 | 소요 시간 |
  |------|------|-----------|
  | App (KakaoTalk) | running | 0.71~0.75s |
  | App (PowerPoint) | cold | 4.2s |
  | URL (Translate) | running | 0.75~0.89s |
  | URL (Case) | running | 0.74~0.87s |

### 변경 후 (AX API 방식)
  구조: 앱 실행 → AX API 폴링(50ms) / AXObserver → 윈도우 감지 즉시 리사이즈

  | 타입 | 상태 | 소요 시간 | 개선폭 |
  |------|------|-----------|--------|
  | App (KakaoTalk) | running | 0.03~0.28s | **3~10배** |
  | App (PowerPoint) | running | 0.03~0.07s | **10배+** |
  | URL (Translate) | running | 0.34~0.44s | **약 2배** |
  | URL (Case) | running | 0.34~0.52s | **약 40%** |

### 수정한 것
  1. AppLauncher: Process+osascript+SystemEvents → AXObserver + AXUIElementSetAttributeValue
  2. ChromeLauncher: Process+osascript+Chrome AppleScript → AX API 윈도우 목록 비교로 새 윈도우 감지
  3. LauncherUtils: setPosition/setSize/axApplyBounds 공용 함수로 통합
  4. 폴링 간격: 고정 딜레이 배열(0.5~2.0초) → 50ms 간격 폴링
  5. Accessibility 체크: AccessibilityPermission 단일 진입점으로 통합
  6. pid 캐싱: Chrome running 시 매 폴링마다 runningApplications 조회 제거
  7. App: AXObserver로 이벤트 기반 감지, 실패 시 폴링 폴백
  8. Chrome 타임아웃: running 시 6초, cold 시 10초

### 남은 병목 (제어 불가)
  - App running: 150ms activate 대기 (macOS 포커스 전환 시간)
  - URL: Chrome 윈도우 생성 시간 (0.3~0.5s, Chrome 내부 처리)
  - 슬립 복귀 후 첫 실행: Chrome warm-up 지연 (1~4초, 간헐적)


## 권한 요구사항
