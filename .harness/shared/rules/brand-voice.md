# Brand & Voice Rule

Chap's identity is **your chap: a friend in your menu bar and notch** (British
"chap" = mate), and **chap** is also the snap of a window landing in place.
`BRAND.md` at the repository root is the source of truth.

Before adding or changing any user-facing text — SwiftUI/AppKit strings, alerts,
menu titles, tooltips, accessibility labels, onboarding, `QAView`, the website
(`docs/index.html`), README, CHANGELOG, or release notes:

1. Read `BRAND.md` and follow its voice rules and signature lines.
2. Keep control labels plain; put wit only in secondary text.
3. Use "Chap" as a verb only for starting, finishing, or snapping into place.
4. When data or permissions are involved, state plainly what Chap keeps.
5. Prefer the fewest, narrowest permissions; a feature that needs broad access
   (for example Screen Recording) needs an explicit product decision first.
6. Update the Korean and English Q&A together.

If a new signature line is introduced, add it to the table in `BRAND.md` in the
same change.
